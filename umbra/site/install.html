01   Install

One binary. No model, no network.

Any executable named entire-<name> on your PATH is dispatched by the Entire CLI kubectl style, so this is the whole installation.

01 Install and run 
go install github.com/u7k4rs6/Umbra/umbra/cmd/entire-umbra@main
entire umbra HEAD --test "pytest -v" --out ./umbra-out
open ./umbra-out/umbra.html

Requires the Entire CLI with Checkpoints enabled and the entire-graph plugin. Use pytest -v, not -q: quiet mode prints no per-test names, so the verifier cannot tell you which test broke, and the verdict degrades to a suite-level pass or fail. Umbra says so in the header when that happens.

02 Reproduce this site's map 
git clone https://github.com/u7k4rs6/Umbra
cd Umbra/umbra/fixtures/app && ./setup.sh
cd ../../..
. umbra/fixtures/app/.venv/bin/activate
entire umbra 1c2cf29 --test "pytest -v"

That reports 8 probes selected and 5 cracked, with a full sweep and 0 leaks. The venv is activated because the runner has to be on PATH: the tests run in a detached worktree that has no venv in it.

02   Flags

The whole command surface.

--test CMDTest runner prefix. Validated test ids are appended as separate argv elements, never joined into a shell string.
--run none|shadow|allWhich selected tests to run. Default shadow. With none the map still renders.
--no-auditSkip the full-suite sweep, which is on by default.
--historyAdd the opt-in scar factor from git history.
--depth 1|2|3Dependency hops. Default 2.
--format table|json|html|packetWhat goes to stdout.
--out PATHWrite umbra.json, umbra.html and umbra.packet.md.
--fail-on umbra|penumbra|failure|leakExit 2 when the condition holds, for use in CI.
--snippetsInclude declaration lines in the report. Off by default.
--allList lit nodes in the table instead of counting them.
--test-root PATHWhere the runner runs, when the project is nested.

Exit codes: 0 completed, 2 the --fail-on condition was met, 1 runtime error.

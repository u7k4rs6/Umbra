Umbra

Umbra shows the code an AI agent's change affects but the agent never looked at. It runs as a plugin for the Entire CLI, takes the dependents from Entire Graph, subtracts what the session actually read according to the checkpoint, and runs the tests that reach whatever is left in shadow.

What the states mean

StateMeaning
● Lit The session read the file with a range covering the symbol, at or after the change began, or it edited the file.
◐ Penumbra Half seen. One of the five tiers below.
○ Umbra Nothing in the session touched or mentioned the file.
? Unknown The transcript carries no tool events and no mentions, so no state can be computed. This is an answer, not an error.

How the ranking works

Every shadowed node gets a score from six factors, and every factor is printed next to the node so you can recompute the number by hand.

  • Relation weight. A direct caller is 3, a data flow or type consumer 2, a caller reached through another symbol 1.5, a co-change file 1.
  • How much depends on it. Multiplied by 1 plus the base-two logarithm of 1 plus its own dependents.
  • How weakly it was seen. Multiplied by 1 for umbra, 0.7 for echo, 0.6 for afterimage, 0.5 for the other penumbra tiers, 0 for lit.
  • Far field. Multiplied by 1.5 when it sits in a different package from the symbol that changed.
  • Fault line. Multiplied by 1.5 when the call site sits inside error handling.
  • Tests. Plus 3 if it is a test, plus 2 if a test reaches it.

Worked from the sample: test_rounding is a direct caller, so 3. It has no dependents of its own, so the second factor is 1. It is full umbra, so 1. It lives in tests/ while the change is in app/, so 1.5. The call site is ordinary code, so 1. It is a test, so add 3. That is 3 x 1 x 1 x 1.5 x 1 + 3 = 7.5.

The beacon override. A call site within four lines of a SAFETY, CRITICAL or INVARIANT comment is pinned to the top of the docket whatever it scored, with the comment shown. Somebody wrote that note by hand; it outranks a heuristic.

The scar factor is opt in with --history: a file with several recent fix commits is multiplied by up to 2. It is off by default because it is noisy, and printed like every other factor when it is on.

The full sweep. After the selected tests, the whole suite runs once. Any test that changed state but was not selected is a leak, and each leak carries the reason the selection missed it: a path deeper than the search went, no resolved call edges from the test file, a path only over a relation Umbra does not follow, or nothing the graph can see at all. The count is printed even when it is zero, because a selection that audits itself is worth more than one that does not.

Install and run

go install github.com/u7k4rs6/Umbra/umbra/cmd/entire-umbra@main
entire umbra HEAD --test "pytest -v" --out ./umbra-out
open ./umbra-out/umbra.html

Requires the Entire CLI with Checkpoints enabled and the entire-graph plugin. Works offline. There is no model anywhere in Umbra.

The runner is pytest -v rather than pytest -q: quiet mode prints no per-test names, so the verifier cannot tell you which test broke.

Reproduce the demo

git clone https://github.com/u7k4rs6/Umbra
cd Umbra/umbra/fixtures/app && ./setup.sh
cd ../../..
. umbra/fixtures/app/.venv/bin/activate
entire umbra 0063443 --test "pytest -v"

The venv is activated because the runner has to be on PATH. Umbra runs the tests in a detached worktree of the commit, so a runner given as a path relative to the repository root will not resolve there, and a runner that cannot start leaves the verifier nothing to parse.

The fixture is seeded: it is built to produce lit, penumbra and umbra nodes, and a signature change that breaks tests in two files the session never opened. The report says so, and so does this page.

Limitations

  • Read evidence is file and line-range based. A mention in the agent's text is attention, not reading, and is ranked as the weakest tier.
  • Graph edges are not complete: reflection, dynamic dispatch and configuration are invisible, so umbra is a lower bound on what was unexamined. The sweep's leak reasons are how you see the gap.
  • Fault lines and beacons are detected by a regular expression window around the call-site line, not by a parser.
  • Ranking weights are hand set and printed. They are a heuristic, not a measurement.
  • One transcript adapter. An agent whose transcript carries no tool records gets the unknown state, which is the correct answer rather than a guess.
